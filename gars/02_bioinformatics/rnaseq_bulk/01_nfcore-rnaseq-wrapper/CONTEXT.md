# Sub-stage 02.01: nf-core/rnaseq Wrapper

## Purpose
Run upstream bulk RNA-seq preprocessing — FASTQ to gene count matrix — through the
GARS-authored `nfcore-rnaseq-wrapper` (decision 0029; the retired ClawBio-skill procedure
was deleted 2026-08-27 after all three switchover criteria were met on a live run). This sub-stage submits the job and returns; it does not
wait for completion. A later invocation reads `STATUS` and collects results.

**The computation is not yours.** The wrapper's `check` validates, `prepare` writes
`params.yaml` and `submit.sh` (requeue guard included), and `collect` runs the exit gate,
writes `OUTPUTS.tsv` and `STATUS`, and harvests the derived-reference cache. Your job is the
dialogue between those calls and the verbatim reporting of what they return. `submit.sh` is
generated by code — never write or edit it yourself.

## Inputs
1. **`01_samplesheets/rnaseq_bulk_samplesheet.csv`** — written by stage 01
2. **`_config/rnaseq_bulk.yaml`** — completed from the stage 02 menus (genome, contrast,
   formula)
3. **The wrapper** — `$GARS_WRAPPERS/nfcore-rnaseq-wrapper/nfcore_rnaseq_wrapper.py`,
   versioned in this workspace (decision 0012); its docstring documents the subcommands
4. Reference (every run): `_references/artifact_types.md`, `_system/gars-env.sh`

## Scope Boundaries
This sub-stage performs the steps in Process and nothing else.

- Never compose a `nextflow` command, and never write or edit `submit.sh` or `params.yaml` —
  `prepare` generates both, and the audited parameter surface is `_config/rnaseq_bulk.yaml`.
  If a parameter seems missing, that is a config or wrapper change to report, not a flag to add.
- Never edit the wrapper's code. If it errors, report the error verbatim and stop.
- Never substitute a hand-written pipeline. If the wrapper cannot run, do not call
  STAR/Salmon by hand and do not "approximate" the result. Report and stop.
- Never modify the samplesheet, the design table, `00_data/`, or anything under
  `01_samplesheets/`.
- Never run the pipeline in the foreground, and never poll for it in a loop. Submit, write
  STATUS, and return.
- Never resubmit a job whose STATUS is `SUBMITTED` or `RUNNING`.
- Never delete or move a populated `run/` directory; `check` refuses it for a reason. Surface
  the refusal.
- Do not interpret the biology. Report counts, paths and QC locations only.
- If you believe a step should deviate, stop and ask. Do not act first and report afterwards.

## Definitions

**Wrapper invocation.** From the workspace root, on stock python — no conda environment is
needed for the wrapper itself (the pipeline's runtime arrives via `gars-env.sh` inside
`submit.sh`):

```bash
python3 _system/wrappers/nfcore-rnaseq-wrapper/nfcore_rnaseq_wrapper.py <subcommand> \
    --project projects/<title>
```

Exit codes are the stage-helper standard: 0 ok, 1 failure (the JSON lists every failure),
2 refused (a gate), 3 usage. Branch on them; never re-interpret a failure as something to fix
silently.

**Failure vocabulary.** As the atacseq wrapper's: `preconditions`, `config`,
`config_unfilled`, `samplesheet`, `pipeline`, `executor_config`, `output_dir`. `collect`
reuses the artifact type names — `counts_gene`, `counts_transcript`, `tpm_gene`,
`bam_genome`, `qc_multiqc` — as its check names.

**Execution venue.** Always `sbatch` — `prepare` writes the batch script from `compute.*`;
a pipeline is never login-node work (decision 0027, no opt-out).

**Requeue and resume.** `submit.sh` carries the guard: a completed run exits cleanly on
re-entry; a crashed or preempted one continues with Nextflow's native `-resume` — a real
crash recovery the ClawBio wrapper could not do (its manifest-gated replay was decision
0029's motivation, alongside the `rnaseq-de` defects).

**Derived-reference cache.** `reference.derived_dir` is keyed by pipeline version
(`nf-core-rnaseq-3.26.0`) and its layout is `index/{star,salmon}` + `genome.transcripts.fa` —
the already-populated 59 GB cache is consumed as-is. Populated → `prepare` passes the
prebuilt indices; absent → the first run builds them with `--save-reference` and `collect`
harvests the published `genome/` directory into the cache atomically. `check` refuses a STAR
cache directory with no `genomeParameters.txt` — a half-built cache is never reused
(decision 0009).

**Reference annotation must carry a biotype attribute.** The genome menu only offers
verified references (Ensembl-native `gene_biotype`), and the wrapper refuses a
`reference.genome` key outright — the iGenomes GRCh38 route killed a full run *after* counts
were written (decision 0005, failure 5).

## Process
1. Reply T1.
2. Read the STATUS file. If it is `SUBMITTED`, `RUNNING`, or `COMPLETE`, stop — stage 02's
   router already handles those states and should not have routed here.
3. Run the wrapper's `check`. Exit 1 → reply T5 with its `failures` verbatim and stop. Do not
   fix causes yourself: `config_unfilled` means the stage 02 menus have not run,
   `samplesheet` means stage 01 must be re-run, `pipeline` means the pinned checkout is
   missing or wrong.
4. Run `prepare`. Exit 1 → reply T5 (same rule). Exit 0 → it wrote `params.yaml`,
   `submit.sh` and the reproducibility bundle; report nothing yet.
5. Submit with `sbatch <sub-stage dir>/submit.sh`. Capture the job ID.
6. Write `STATUS` as `SUBMITTED <job_id> <iso8601>`. Reply T2 and stop. Do not wait, poll,
   or sleep.
7. **On a later invocation** where STATUS is `SUBMITTED` or `RUNNING`: query `sacct`/`squeue`
   for the job. If still active, update STATUS to `RUNNING <job_id> <iso8601>`, reply T3,
   stop.
8. If the job has finished, run `collect` with `--model "<the exact model id you are running
   as>"` (decision 0024). Exit 2 → the run did not actually complete: write `STATUS` as
   `FAILED <iso8601>`, reply T4 with the wrapper's error and the Slurm log path, stop.
   Exit 1 → the exit gate failed: write `FAILED`, reply T4 with its `failures` verbatim, stop.
9. Exit 0 → `collect` has written `OUTPUTS.tsv` and `STATUS COMPLETE`. Append its
   `history_entry` to the project's `HISTORY.md` **verbatim**, replacing `<ISO-8601 date>`
   with today's date, and reply T6.

## OUTPUT
Written to `projects/<project_title>/02_bioinformatics/rnaseq_bulk/01_nfcore-rnaseq-wrapper/`:

| Artifact | Contents |
|---|---|
| `STATUS` | Sub-stage state. The authority on completion. |
| `params.yaml` | The audited pipeline parameters, generated by `prepare`. |
| `submit.sh` | The generated Slurm script, requeue guard included. Re-runnable by hand. |
| `preflight/check_result.json` | Preflight verdict. Diagnostic only. |
| `reproducibility/` | `manifest.json` (input checksums, pipeline commit), `commands.sh`. |
| `logs/` | Slurm stdout/stderr. |
| `OUTPUTS.tsv` | Artifacts by type, written by `collect`. How 02.02 finds the count matrix. |
| `run/` | The pipeline's own output tree: `results/`, the completion marker. |

`00_data/` and `01_samplesheets/` are never modified.

## Human check
Open `run/results/multiqc/<aligner>/multiqc_report.html` and read the alignment and
duplication rates before letting anything consume the counts. Confirm the sample count in the
report equals the sample count in the samplesheet — a sample lost to a failed process shows
up here and nowhere downstream.

If strandedness was left at `auto`, check the RSeQC `infer_experiment` result and set it
explicitly in `_config/rnaseq_bulk.yaml` for future runs.
