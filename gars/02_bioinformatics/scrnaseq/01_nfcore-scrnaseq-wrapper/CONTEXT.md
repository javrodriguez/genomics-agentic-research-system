# Sub-stage 02.01 (scrnaseq): nf-core/scrnaseq Wrapper

## Purpose
Run upstream single-cell RNA-seq processing — FASTQ to per-cell count matrices — through
`nfcore-scrnaseq-wrapper` (decisions 0028, 0039). This sub-stage submits the job and returns;
it does not wait for completion. A later invocation reads `STATUS` and collects results.

**The computation is not yours.** The wrapper's `check` validates, `prepare` writes
`params.yaml` and `submit.sh` (including the requeue guard), and `collect` runs the exit gate
and writes `OUTPUTS.tsv` and `STATUS`. Your job is the dialogue between those calls and the
verbatim reporting of what they return. `submit.sh` is generated by code — never write or edit
it yourself.

## Inputs
1. **`01_samplesheets/scrnaseq_samplesheet.csv`** — written by stage 01
2. **`_config/scrnaseq.yaml`** — completed from the stage 02 menus (genome, protocol, aligner)
3. **The wrapper** — `$GARS_WRAPPERS/nfcore-scrnaseq-wrapper/nfcore_scrnaseq_wrapper.py`,
   versioned in this workspace (decision 0012); its `SKILL.md` documents the subcommands
4. Reference (every run): `_references/artifact_types.md` for the produced types,
   `_system/gars-env.sh` for the runtime

## Scope Boundaries
This sub-stage performs the steps in Process and nothing else.

- Never compose a `nextflow` command, and never write or edit `submit.sh` or `params.yaml` —
  `prepare` generates both, and the audited parameter surface is `_config/scrnaseq.yaml`.
  If a parameter seems missing, that is a config or wrapper change to report, not a flag to add.
- **Never guess or "detect" the protocol.** The library chemistry comes from the user through
  the stage 02 menu. Do not infer it from read lengths, file names, or the data. A wrong
  protocol produces a scrambled matrix rather than an error.
- Never change the aligner to work around a failure. simpleaf, star and kallisto give
  different cell counts at the margins; swapping one for another is a re-analysis, not a retry.
- Never edit the wrapper's code. If it errors, report the error verbatim and stop.
- Never substitute a hand-written pipeline. If the wrapper cannot run, do not call STARsolo,
  alevin-fry or kallisto by hand and do not "approximate" the result. Report and stop.
- Never open, filter or subset the produced `.h5ad`. QC, clustering and annotation are a
  separate concern; this sub-stage produces the matrix and stops.
- Never modify the samplesheet, the design table, `00_data/`, or anything under
  `01_samplesheets/`.
- Never run the pipeline in the foreground, and never poll for it in a loop. Submit, write
  STATUS, and return.
- Never resubmit a job whose STATUS is `SUBMITTED` or `RUNNING`.
- Never delete or move a populated `run/` directory; `check` refuses it for a reason. Surface
  the refusal.
- Do not interpret the biology. Report cell and sample counts, paths and QC locations only.
- If you believe a step should deviate, stop and ask. Do not act first and report afterwards.

## Definitions

**Wrapper invocation.** From the workspace root, on stock python — no conda environment is
needed for the wrapper itself (the pipeline's runtime arrives via `gars-env.sh` inside
`submit.sh`):

```bash
python3 _system/wrappers/nfcore-scrnaseq-wrapper/nfcore_scrnaseq_wrapper.py <subcommand> \
    --project projects/<title>
```

Exit codes are the stage-helper standard: 0 ok, 1 failure (the JSON lists every failure),
2 refused (a gate), 3 usage. Branch on them; never re-interpret a failure as something to fix
silently.

**Failure vocabulary.** Each failure names its check: `preconditions` (an input file is
missing), `config` (a key is absent or invalid — including an aligner outside the menu, or a
protocol the aligner does not support), `config_unfilled` (`<REQUIRED>` markers remain — the
stage 02 menus have not run), `samplesheet` (header, paths, or a duplicate sample id),
`pipeline` (the pinned checkout is missing or describes the wrong tag), `executor_config`
(`nextflow.slurm.config` carries a `params` block), `output_dir` (`run/` is populated without a
completion marker). `collect` reuses the artifact type names — `h5ad`, `qc_multiqc` — as its
check names, so a gate failure says which artifact is wrong.

**The `sample` column is the sample id.** nf-core/scrnaseq's `assets/schema_input.json` gives
`sample` the meta key `id`. This differs from the ATAC/ChIP-family sheets, where `sample` is
the *group* and rows repeat per replicate (decision 0035). Here a repeated value is an error,
and `check` refuses it: two rows sharing a sample id would be merged into one barcode space.

**Protocol and aligner are a pair.** `check` reads the pinned checkout's own
`assets/protocols.json` and refuses a protocol the chosen aligner does not support. This exists
because nf-core/scrnaseq passes an unrecognised protocol to the aligner *verbatim* rather than
rejecting it, so the mistake would otherwise run to completion and publish a wrong matrix.
`auto` is never valid here: it works only with the cellranger aligners, which this wrapper does
not offer.

**Execution venue.** The pipeline always runs under `sbatch` — `prepare` writes the batch
script from `compute.*` and there is no login-node mode (decision 0027).

**Requeue and resume.** `submit.sh` carries the guard: a completed run exits cleanly on
re-entry, a crashed or preempted one continues with Nextflow's native `-resume`.

**Derived-reference cache.** `reference.derived_dir` is keyed by pipeline version
(`nf-core-scrnaseq-4.2.0`). Populated → `prepare` passes the prebuilt index; absent → the first
run builds it with `--save-reference` and `collect` harvests it into the cache atomically.

**Produced artifacts.** `h5ad`, `qc_multiqc` — see `_references/artifact_types.md`. The exit
gate checks **content**: every sample in the samplesheet must have produced its own converted
matrix under `mtx_conversions/<sample>/`, because a sample lost to a failed process would
otherwise vanish silently into a combined matrix built from fewer samples (decision 0010).
A `.h5ad` is HDF5 and the wrapper is stdlib-only, so cell-level checks are deliberately **not**
attempted here; they belong to a downstream analysis sub-stage that runs under `gars-bio`.

## Process
1. Reply T1.
2. Read the STATUS file. If it is `SUBMITTED`, `RUNNING`, or `COMPLETE`, stop — stage 02's
   router already handles those states and should not have routed here.
3. Run the wrapper's `check`. Exit 1 → reply T5 with its `failures` verbatim and stop. Do not
   fix causes yourself: `config_unfilled` means the stage 02 menus have not run, `samplesheet`
   means stage 01 must be re-run, `pipeline` means the pinned checkout is missing or wrong.
4. Run `prepare`. Exit 1 → reply T5 (same rule). Exit 0 → it wrote `params.yaml`, `submit.sh`
   and the reproducibility bundle; report nothing yet.
5. Submit with `sbatch <sub-stage dir>/submit.sh`. Capture the job ID.
6. Write `STATUS` as `SUBMITTED <job_id> <iso8601>`. Reply T2 and stop. Do not wait, poll, or
   sleep.
7. **On a later invocation** where STATUS is `SUBMITTED` or `RUNNING`: query `sacct`/`squeue`
   for the job. If still active, update STATUS to `RUNNING <job_id> <iso8601>`, reply T3, stop.
8. If the job has finished, run `collect` with `--model "<the exact model id you are running
   as>"` (decision 0024). Exit 2 → the run did not actually complete: write `STATUS` as
   `FAILED <iso8601>`, reply T4 with the wrapper's error and the Slurm log path, stop.
   Exit 1 → the exit gate failed: write `FAILED`, reply T4 with its `failures` verbatim, stop.
9. Exit 0 → `collect` has written `OUTPUTS.tsv` and `STATUS COMPLETE`. Append its
   `history_entry` to the project's `HISTORY.md` **verbatim**, replacing `<ISO-8601 date>`
   with today's date, and reply T6.

user asks a direct question, answer it from this workspace's own files — the contracts,

## Human check
Open `run/results/multiqc/multiqc_report.html` and read the per-sample **estimated cell
number**, **median genes per cell**, and **fraction of reads in cells** before anything
consumes this matrix. Confirm the cell counts are within the same order of magnitude as the
number you expected when the library was loaded — a sample recovering a hundred cells where you
loaded ten thousand is a failed library or the wrong chemistry, and nothing downstream will
flag it.
