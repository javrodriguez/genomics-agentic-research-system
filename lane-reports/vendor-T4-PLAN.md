PRINCIPLE (glitch-b5, governing every section): the Gap Study compares models, so a GPT or Gemini take is checked at least as strictly as a Claude Code take on every check.
Where this plan cannot match a check for a vendor, the one table says so, that check is NOT COMPARABLE for that arm, and the study publishes it as such; nothing is silently weaker.
A check whose only source would be the driver's own record is never a pass: it is PENDING until an independent reader exists or a ruling marks it NOT COMPARABLE.
PENDING, per road (the table's header gives the code): a take is refused under the row's reason id with "no vendor reader yet" and routes as a Claude Code take with that reason routes: harness-error after its first agent turn (operator-reason-after-first-turn), unless a row of higher precedence also matches (rate-limit routes pause; cgroup-kill routes aborted, except, at cbf3c231, when the reasons include harness-condition-violated), which is the same for every arm; a walk records the reason and counts as coverage only as a Claude Code walk with that reason does; the freeze (section 7) keeps an arm with any unsettled PENDING row out of a frozen order.
A PENDING refusal is never written under an event id (study-materials-reached, account-email, read-outside-the-checkout, which check4 lifts into events, D/check_take.py:1970-1982); a PENDING reach item refuses under transcript-unreadable.
One source of truth for PENDING (review 10ac86f MINOR 3): every vendor PENDING refusal is raised through one helper keyed by its row of check_take.VENDOR_PENDING_ROWS (section 7), and a test binds the helper's call keys to the map's keys per harness.

The brief's four classes, as used in section 1: AS IS = APPLIES AS IS; READER = APPLIES WITH A VENDOR READER (the reader is named); BYTES = CANNOT BE CHECKED WITHOUT REAL BYTES (the walk evidence that settles it is named; PENDING until then); N/A = DOES NOT APPLY (why is given).
