Cause, from `evals/check_results.py:235-268` (`check_results_binding`): each results file is bound to the pre-registration **only** by the whole-file `prereg_sha256` it recorded, plus a task-id and state/verdict shape check. So the number a human reads in the artifact can drift from the pre-registration while the checker prints `clean`.

Fair scoping of the severity: the *grading* is still pinned — `check_thresholds` verifies the prereg's bytes and re-checks nine named constants against the live grader modules, and the graders and generators are sha256-pinned. What is unbound is the published restatement, i.e. exactly the surface a reader is pointed at. A one-line comparison of `results["threshold"]` against the frozen task entry would close it, and a mutation test on that comparison would keep it closed.

The sharp edge: the **same** suite already handles this prerequisite correctly one test over —
`skipped 'the neutralised set-a fixture is not on disk in this checkout'` — so the harness knows the fixture may be absent and skips-with-a-named-reason there, while `test_a_compliant_take_passes` hard-fails instead. ## Additional observations (not part of the checklist)

1. **`evals/results/confounded-refusal.json` is not machine-portable.** Re-running `run.py --all` from my clone changed exactly two lines: the absolute `transcript` path (`/Users/rodrij92/glitch/workspaces/…` → my clone's path). Everything else, including both `transcript_sha256` values and every graded label, reproduced byte-for-byte — good news for determinism, but the artifact records a machine path, so `git status` is dirty after any reproduction run and the file cannot be diffed across machines. Storing the path repo-relative would make the published result byte-stable for exactly the reader the document invites.
2. **`docs/RESULTS.md`'s "3 of 5 scored" has a mixed denominator.** The table has 6 rows because project 3 is split into 3a/3b; 3 rows carry verdicts, but only projects 1 and 2 are *fully* closed — project 3 is half scored (3a done, 3b not). "3 of 5" counts row-units in the numerator and project-units in the denominator. Given how carefully the same paragraph argues that a campaign must not report a denominator it did not earn, this is worth one clarifying word.
3. **Secret-scan warnings during this session were innocent** — the flagged high-entropy strings were sha256 content digests (`transcript_sha256`, `git_blob_sha`, the prereg digest) and the scratchpad's session UUID in a file path. No credential appeared in any output.
