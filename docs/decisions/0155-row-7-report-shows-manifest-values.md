# Row 7 follow-up 0155: the report shows the project's own manifest values

Follow-up to [0075](0075-row-7-claims-and-report-renderer.md) (the claims table and the report renderer) and [0079](0079-row-7-delegated-approval-of-protected-additions.md), whose bytes are unchanged.
Every ruling here is **the lane's**, made under the owner's standing delegation of 23 September 2026 and ruled by the lane's coordinator on 26 September 2026; no sentence in this record is the owner's.
0156 is the lane's delegated approval of the protected change; this record does not write it.

## Context

`gars/_system/claims/render_report.py` rendered four report sections as fixed placeholders and never read the values the manifest supplies for them: data and classification (`UNKNOWN (owned by row 6: data_class, venue, purpose)`), the genome and model line in methods (`UNKNOWN (owned by row 6)`), the `commands.sh` reproduce line (`UNKNOWN (owned by row 6)`) and cost (`UNKNOWN (owned by row 11: docs/ledger.csv has no per-run cost source)`).
0075's source table assigned those sections to rows 6 and 11 before either existed.
Row 6 has since written every one of those values into the sub-stage's `reproducibility/manifest.json` (`gars/_system/wrapperlib.py`): `data_class`, `venue`, `purpose` and `agreement_ref` (schema group 11), `reference` with its build, annotation release, FASTA and GTF hashes and the registry comparison (group 6), `command` with the path and sha256 of `commands.sh` (group 7), `agent_model` and `model_steps` (groups 16 and 18), and `resources` from scheduler accounting (group 10).
So every report a visitor opened read as unfinished in four places, while the manifest the report cites held the answers.
Row 10's round U found it on 25 September 2026 (0136 names it as a row 7 product defect to be fixed in its own follow-up).
On public main `9896512`, a collect-shaped manifest carrying every field above still rendered exactly the four placeholders.

## Decision

**Ruling 0155 (the lane's).** `render()` reads the four sections from the manifest; nothing else in the renderer changes.

1. **Data and classification** reads `data_class: <v>; venue: <v>; purpose: <v>`, with `; agreement_ref: <v>` only when it is set.
2. **Methods** ends with two paragraphs in place of the genome/model placeholder.
   `Reference:` gives `build`, `annotation_release`, `fasta_sha256` and `gtf_sha256`; when the registry `comparison` is not `matched` it adds `registry check: <comparison> (<reason>)`, so a missing or mismatched hash is said plainly.
   `Model steps:` gives one `model_id / prompt_id / prompt_sha256 / routing_rule_id` item per `model_steps` entry, or `no model-mediated step (agent_model: none)`.
3. **Reproduce this analysis** gives the `command` path (relative to the sub-stage folder) and its sha256, as plain text; the file is never opened, so the three-inputs rule of 0075 stands.
4. **Cost** gives the manifest's `cost` string when there is one, else `Not recorded: GARS does not meter per-run cost yet, and this manifest has no cost field.`; then, when `resources` holds scheduler accounting (anything but the local `not applicable` form), `Resources consumed (scheduler accounting): <resources>`.
5. **Absence is said, never invented.** A missing or empty top-level value renders the constant text ``not recorded (the manifest has no `<key>`)`` naming the key; a missing sub-field renders `not recorded`.
   "Empty" is `None`, `[]`, `{}` or a blank string (an empty object is included so it never renders as escaped braces).
   The text is fixed by code; every manifest-supplied value still goes through `display()` (HTML escape, Markdown escape, newline flattening), so no value can add a section, heading, table row or HTML.
6. **`unknown()` and `display()` are byte-identical to `9896512`.** Row 10's pinned science prompt cites `unknown()`'s literal form (0136), so the per-claim fallbacks keep it (D1 below).

Tests move with the change: `gars/tests/test_render_report.py` gains six tests (supplied values escaped and no row 6 or row 11 owner anywhere; `agent_model: none`; registry comparisons; hostile values in every new field; missing and empty values; cost and resources absence), its golden report is regenerated by the renderer, and row 10's `tests/test_bio_faults_pipeline.py` now asserts that a clean built report carries no `UNKNOWN` at all (`test_clean_report_has_no_unknown`, renamed from `test_clean_report_unknown_only_renderer_placeholders`, with the one `FAULTS` entry in `tests/test_bio_faults_faults.py` that named it following the rename).
The suite total moves from 1111 to 1117.

**Row 10's instrument text.** `evals/bio-faults/INTERFACE.md`'s sentence that "the inherited renderer still emits UNKNOWN for hard-coded sections" is superseded at this landing and left byte-identical (no file pins its hash; it is row 10's instrument).
Row 10's measured runs ship from its own frozen clone at `9896512`, so this landing moves none of its cases.
Row 10's synthetic base writes `commands` and `commands_sha256`, not the schema's `command` object, so its reports read the reproduce line as `not recorded`; its generator is unchanged because its base fingerprints are pinned (D3).
In future builds the four sections no longer carry the placeholder form, so a science reviewer reads them fully in scope.

## What this does not close

- **D1** The per-claim fallbacks `UNKNOWN (owned by row 7: claim writer)` and `UNKNOWN (owned by §14 QC dispositions)` still read as row ownership. Changing them breaks row 10's pinned prompt coupling; they wait for the parked prompt edit.
- **D2** No per-run cost producer exists; the cost section says so. Metering is row 11's.
- **D3** Row 10's base uses `commands`/`commands_sha256`, not the schema's `command`; aligning it is row 10's call after its measured runs.
- **D4** (review F-1, MINOR, deferred by the lane's stop rule) A `cost` that is present but not a string, and a `model_steps` that is present but not a list, render the absence sentence although the key exists. The schema defines no `cost` field and writes `model_steps` as a list, so only a hand-made manifest reaches this.
- Validating what a manifest says is `manifest_check.py`'s job, not the renderer's.

## Test

`python3 -m unittest discover -s gars/tests -p test_render_report.py` (20 tests) is the acceptance.
It must fail when any of the four sections stops reading the manifest, when a supplied value is passed without `display()`, when an empty value renders as `UNKNOWN`, when the two methods paragraphs are joined, or when the registry check is dropped; the lane's mutation proof at the branch head killed 9 of 9 such mutants with the unchanged control green.
`tests/test_bio_faults_pipeline.py` must fail when a clean built report carries any `UNKNOWN`.
The landing's evidence is recorded in 0156.
