# A GARS wrapper clones the ClawBio behavior, not the ClawBio architecture

## What happened

Wrapper #1 (`nfcore-atacseq-wrapper`, decision [0012](0012-gars-authored-wrappers-live-in-system.md))
had a design question the research left open: the ClawBio wrappers it "clones" are 12-module,
2.1 MB skills, and cloning that architecture four times was the strongest argument *against*
building wrappers at all (assay-expansion.md §6.2a's cost note).

## Decision

What gets cloned is the **behavioral contract**, in the `_system/` idiom GARS already trusts:
one stdlib Python file per wrapper, JSON on stdout, exit codes 0/1/2/3, deterministic bytes,
tested offline by `tests/run_tests.py`. The behaviors carried over from 02.01's hard-won
lessons — preflight before submission, local pinned checkout only (the GitHub REST API is
rate-capped), `--profile apptainer`, work on scratch, no `params` block in the executor
config, content-checking exit gates, structured failure codes — are requirements on *what the
wrapper does*, not on how many files it is. A ~600-line helper meets all of them; the module
count was ClawBio's shape, not the contract's.

Three deliberate improvements over the ClawBio surface, each fixing a recorded defect:

1. **`submit.sh` is generated by `prepare`, not written by the agent.** The rnaseq contract
   has the agent compose the batch script from Definitions prose; that is a deterministic
   artifact, so it is code's job ([0011](0011-deterministic-artifacts-in-stages-00-01.md)).
   The requeue guard ships inside the generated script and cannot be mis-transcribed.
2. **Crash recovery is Nextflow's native `-resume`.** The ClawBio wrapper rejects `--resume`
   without its success manifest, so a crashed run could never be continued — a limitation of
   its bookkeeping, not of Nextflow. Running the pipeline directly restores real resume: the
   guard adds `-resume` whenever a session exists, and a preempted job continues instead of
   restarting from zero.
3. **The version check is honest.** No `_MANIFEST_VERSION_RE` lookbehind bug to work around:
   the checkout is verified with `git describe --tags` against the pin in
   `workspace.PIPELINES`, the same source `configure.py` keys the cache with.

## What grew around it

- **`workspace.PIPELINES`** — one pinned pipeline per assay, the single source for cache
  keying and checkout verification.
- **The genome registry carries genome facts, per assay** (`genomes.md`): the derived-cache
  cell became a *root* that `configure.py` keys with the assay's pipeline, and the row gained
  `Mito contig` and `MACS gsize` — properties of the assembly that were previously headed for
  per-project hand-typing. Choosing a genome now sets five things that cannot be mismatched.
- **`configure.py` decisions are per-assay** (`ASSAY_DECISIONS`): de assays choose a contrast,
  peaks assays choose narrow|broad from a closed two-value menu ([0020](0020-config-decisions-come-from-menus.md)).
- **Four artifact types** — `peaks`, `peaks_consensus`, `counts_peaks`, `bigwig` — extended
  through the sanctioned route (closed means closed; extension, not invention), with the rule
  that a directory-valued path is allowed only for inherently per-sample sets.

## The template for wrappers #2–#4

chipseq, cutandrun and methylseq clone *this* wrapper: same subcommands, same failure
vocabulary (drift-checked against each contract by `tests/check_contracts.py`), same
prepare-generates-submit pattern. What varies per assay is `build_params`, the exit-gate
paths, and the config template — which is the diff the research predicted.
