# Security fix and the AWS Batch executor template: a Batch config admitted only as an exact rendering of its protected template, and a stricter executor-config check for slurm

Follow-up to [0039](0039-the-executor-is-a-workspace-setting.md) (the executor seam) and to row 4's typed policy surface ([0058](0058-row-4-typed-surface-and-attack-list.md), ruling 3A), whose bytes are unchanged.
Every ruling here is **the lane's**, made under the owner's standing delegation of 23 September 2026 and ruled by the lane's coordinator on 30 September 2026; no sentence in this record is the owner's.
0252 is the delegated approval of the protected change; this record does not write it.

## Context

`check_groovy` (added on 21 Sep 2026 in `6c4b631`, row 4) admits an executor config only when, with comments stripped, each single-quoted literal replaced after an R-075 charset check, and whitespace removed, it equals the shape of `_templates/config/nextflow.slurm.config`.
It compared with that one file whatever the descriptor's `nextflow_config` named, so the launch pad's `nextflow.awsbatch.config` (written by the demo's `gen_executor_config.sh --head local`) was refused at `a80df2d` and at `37a8d94` with "R-098/§9.6: unregistered Groovy grammar; use the seeded executor config".
The slurm grammar cannot say what the config of the demo's run on Batch of 3 Sep 2026 carried: `aws.region`, `aws.batch.cliPath`, `aws.batch.maxSpotAttempts`, the transfer settings, `process.resourceLimits`, `process.resourceLabels`, and the null-exit arm of `errorStrategy`.
The lane's coordinator ruled option (b) on 30 Sep 2026: one fixed protected template per descriptor config name, a missing template refused, slurm unchanged, the shape lock and the literal check kept.
After two review rounds found ever-narrower holes in the shape comparison, the coordinator ruled on 30 Sep 2026 (about 08:20 EDT, under the owner's delegation; relayed to the lane at or before 08:19 EDT by `date`) that the design was the defect: the Batch config is admitted only by EXACT RENDER EQUALITY with its template (item 5), and slurm keeps the shape check with reviews r1's and r2's fixes.

Reading the code for the widening found a defect at `37a8d94`, reproduced without a model.
The nf-core wrappers pass `ex.nextflow_config_path(project)` with `-c`, which is `<project>/_config/<name>`; `check_executor_config` re-derived the file from the base name.
For a descriptor naming `sub/nextflow.slurm.config`, preflight read `_config/sub/sub/nextflow.slurm.config` while the wrapper passed `_config/sub/nextflow.slurm.config`; for `../nextflow.slurm.config`, preflight read a file two levels up and the wrapper one level up.
A slurm-shaped decoy at the checked path let a config with `process.beforeScript` through (both names printed ADMITTED with the evil file at the wrapper's path).

## Disclosed pre-existing finding: the security fix in this change

This change is a security fix as well as a widening, so that an approval of it is an approval of the fix, knowingly (the coordinator's ruling of 30 Sep 2026, under the owner's delegation).
- **What.** `check_groovy`'s shape stripped `//` comments before it read any string, so text after a `//` inside a double-quoted string left the shape while staying in the file, and whitespace inside a double-quoted string was dropped; the R-075 check never saw the hidden text (item 4, L5-R1-1 and L5-R1-2).
- **When it entered.** The comment strip came with `check_groovy` itself, in `6c4b631` (21 Sep 2026, row 4), landed on main by `9b76e3f` (22 Sep 2026).
  At `6c4b631` the slurm template held no double-quoted string outside its comments, so, by the lane's reading of those bytes (not probed at that commit), there was no string to hide text in yet.
- **The ways in.** The slurm template's `fields` string, added by `94249c5` (row 6) and landed by `bc5f98e` (24 Sep 2026), is on public main `37a8d94`.
  Measured by the lane at `37a8d94`'s own code (`check_groovy` on the seeded slurm template with one inert change in `fields`): a `//` followed by a second `process.maxRetries` statement, the string closed on the next line, was ADMITTED, and so was one added space; at this change both are refused.
  The AWS Batch template adds five more double-quoted strings (`"awsbatch"`, `"retry"`, `"finish"`, `"10/1min"` and the trace file), besides its own `fields`, so without the fix the widening would have multiplied the places the defect could sit.
  The review's probes (in the trace `file` string, `submitRateLimit` and slurm's `fields`) were admitted too; whether Nextflow would run hidden text was not measured here (R5).
- **The fix.** Item 4: `shape` reads strings before comments and keeps each double-quoted string byte for byte; test 12 refuses both changes in every double-quoted string of both templates. For the Batch config the render ruling (item 5) replaces the shape altogether: its every byte outside the three slots is fixed.
- **Two more pre-existing items, found by review r2 and closed here (item 4).** L5-R2-1: the shape at `37a8d94` removed all whitespace and comments, so word and line boundaries were never compared; measured by the lane at `37a8d94`'s own code on the seeded slurm template with inert edits, an identifier split by a space, by a newline and by a comment, and two statements joined on one line, were each ADMITTED, and each is refused here.
  L5-R2-2: a descriptor that names no config (`name: local`, or `name: slurm` with a blank `nextflow_config`) made preflight return early while the wrapper passed its fallback `nextflow.slurm.config` unchecked; at `37a8d94` the lane's probe had preflight return no failure for a fallback file that `check_groovy` itself refuses, and here the file is checked.

## Decision

**Ruling 0251 (the lane's).**

1. **The template** (`gars/_templates/config/nextflow.awsbatch.config`, protected under `_templates/`).
   It declares exactly three slots, each once and inside single quotes: `{{queue}}` (`process.queue`), `{{goal}}` (the one `process.resourceLabels` value) and `{{region}}` (`aws.region`).
   Every other byte is fixed, comments and spacing included: `aws.batch.cliPath` is `'/opt/nf-tools/bin/aws'`, not a slot, because the demo's terraform defines one install path for every host (`infra/batch.tf:316`, `aws_cli_path`, the one value behind both its `batch_cli_path` outputs); the double-quoted `executor = "awsbatch"`, the `errorStrategy` outcomes `"retry"` and `"finish"`, `submitRateLimit = "10/1min"` and the trace `file` and `fields` are fixed too.
   Line by line:
   - `executor`, `queue`, `resourceLimits = [ cpus: 4, memory: 14.GB, time: 8.h ]`, `errorStrategy` with the null arm, `maxRetries = 3`, `aws.region`, `aws.batch.cliPath`, `maxSpotAttempts = 5`, `maxParallelTransfers = 4`, `maxTransferAttempts = 3`, `queueSize = 20` and `submitRateLimit` are the 3 Sep config's lines, with the reasons its generator's comments give (the clamp to the largest instance type, the reclaimed host reporting no exit status, the CLI path that must equal the hosts' install path, spot reclamation as normal weather).
   - The clamp values are fixed, not slots: both Batch compute environments the demo defines use the same instance types, largest `m5.xlarge`, so no known site needs another value, and a site that does changes a protected template with its own record.
   - `resourceLabels = [ goal: '…' ]` is always present with exactly one key, so a job's cost-allocation tag can never be forgotten; a rehearsal and a take differ only in the value. The 3 Sep config's second key (`project`) is not admitted.
   - The `errorStrategy` outcomes are double-quoted, which departs from the 3 Sep form (`'retry' : 'finish'`): as single-quoted literals they would have been site values under the shape check, and `'retry' : 'retry'` or `'ignore'` would pass (the investigation's candidate showed the first passes under the slurm grammar). The closure is the 3 Sep closure otherwise, token for token.
   - The `trace` block is the slurm template's, with its file double-quoted and two fields added: collect's manifest reads `run/pipeline_info/gars_trace.txt` for each process's container, start and complete (`trace_evidence`), and the 3 Sep config had no trace block.
     The added fields are `native_id` (the launch pad's `jobs` finds the Batch job ids there; D `scripts/launchpad.sh:893` in the demo workspace, `:940` in the pad lane's worktree requires it with `task_id` and `name`) and `exit` (the pad's smoke verdict stops without it, D `scripts/batch_smoke.sh:124-128`); the rest keep the slurm order (F-L3-3, the lane executor's in-spec ruling of 30 Sep 2026, open to the coordinator's review).
     That a `-c` config's trace scope replaces nf-core's own is the pad lane's inference, not measured here (R5); `trace_evidence` reads columns by header name (`wrapperlib.py:1148`), so the added columns are read past (test 14). `report`, `timeline` and `apptainer.pullTimeout` are left out: nothing in the manifest reads the first two, and Batch supplies each container itself.
   - No `params`, `workDir`, `beforeScript`, `includeConfig` or `$` appears in it (a test pins this).
2. **The check** (`gars/_system/wrapperlib.py`).
   `check_executor_config` hands the descriptor's name to `check_groovy`, which takes `executor_template(name)`: a name with a rendered template (item 5) is checked by exact rendering, any other (today the slurm one) by the shape (item 4) (`wrapperlib.py:527-536`).
   `executor_template` is the one door from a name to a template: the name must fully match `nextflow\.[a-z0-9]+\.config`, and the template must be a regular file, not a symlink, directly in `_templates/config/` as reached without a symlink (its resolved parent equals the folder's path); anything else is refused as "R-098/§9.6: <name> names no protected executor template; use the seeded executor config".
   For slurm, the R-075 literal check and the refusal text for a grammar mismatch are unchanged, and `check_groovy` called with no name still compares with the slurm template; the shape function changed after reviews r1 and r2 (item 4).
3. **The file checked is the file passed.**
   `check_executor_config` refuses a config that does not sit directly in a `_config/` folder ("R-098/§9.6: <file> is not a file directly in the project's _config/; use the seeded executor config"), and `executorlib.validate` refuses a descriptor whose `nextflow_config` contains `/` or is `.` or `..` ("R-075: nextflow_config must be a bare file name in _config/").
   The second rule also reaches an absolute name that lands in another project's `_config/`, where preflight reads that other project's descriptor: `write_submit_sh` validates the requesting project's descriptor and raises before `submit.sh` is written, as it already does for a backend outside the enum.
   The project whose descriptor preflight reads is the parent of the passed file's `_config/` folder, never found by walking up, and the fence runs before the descriptor is read (item 4).
   A `_config/<name>` that is a symlink is admitted only as `scripts/rerun_check.py`'s `bind_project` makes one for a replay (`rerun_check.py:233-243`, row 8's `633778a`, which links each of the original run's `_config` files into the fresh replay project): its final realpath, a chain followed to its end, must have the descriptor's config name ("R-098/§9.6: <name> resolves to a different config name (<target>)") and lie inside this workspace's projects, `<workspace>/projects` as stage 00 registers them, compared as a path (`relative_to` on the resolved paths), never as a string prefix ("R-098/§9.6: <name> resolves outside this workspace's projects") (`wrapperlib.py:366-382`, `EXECUTOR_PROJECTS` `:398`).
   The bytes then checked, and hashed into the manifest, are the target's, the bytes Nextflow reads through the link. Review r3 had first refused every link (R3-3); the full suite found that refusal broke every replay of `test_rerun_check.py` (14 cases), so the lane executor ruled option A on 30 Sep 2026 and the coordinator added the containment rule (both under the owner's delegation); a link re-pointed after the check stays R3's risk, as a rewritten regular file is.
4. **Review r1's findings (fixed in this change).**
   - **L5-R1-1 (MAJOR), a `//` inside a double-quoted string.** The shape stripped `//[^\n]*` before it read any string, as it had since `6c4b631`, but in Groovy a `//` inside a string literal is string text, not a comment.
     So string text after a `//` left the shape while staying in the file, and a later line that shaped to the missing closing quote made the comparison equal again; the R-075 check never saw the hidden text, because it ran only on single-quoted spans that survived the strip.
     The reviewer's probes were admitted in the trace `file` string, `submitRateLimit` and the slurm template's own `fields` string, so the defect was already in the slurm grammar at `37a8d94`; the Batch template's six double-quoted strings would have multiplied the places it could sit.
     `shape` now reads the text left to right and a quoted string is read whole before any comment is considered: each single-quoted literal passes R-075 and becomes one site-value token, and each double-quoted string is one token kept byte for byte, whitespace included; token lists, not joined text, are compared.
     As first written for review r1, it still dropped every `//` comment and all whitespace outside strings and made every other character its own token; review r2 found that too loose (L5-R2-1, below), and the shape is now `wrapperlib.py:474-525`.
     An unterminated quote is refused.
   - **L5-R1-2 (MINOR), whitespace inside a double-quoted string** was dropped before comparison; the same change keeps it, so `"aws batch"` no longer has the shape of `"awsbatch"`.
   - **L5-R1-3 (MINOR, from before this change), a nested `_config/`.** Preflight found its project with `config_root_for(<the config's folder>)`, which walks up to the nearest folder holding a `_config/`.
     A `<project>/_config/_config/executor.yaml` made that walk stop at `<project>/_config`, so preflight read that descriptor (`name: local`, no config demanded) and returned early, while the wrapper still passed the project's own `_config/nextflow.awsbatch.config` with `-c`, unchecked.
     The project is now the passed file's `_config/` folder's parent (`wrapperlib.py:349-354`), which is the project the wrapper built the path from; closed.
   - **L5-R2-1 (MAJOR), word and line boundaries.** Outside strings the r1 shape made every character its own token and dropped all whitespace, newlines and `//` comments, so identifier and statement boundaries were never compared: `max Retries = 3`, an identifier split by a newline or by a comment, and two statements joined on one line all had the template's shape, while Groovy reads a split identifier as two statements (a split `resourceLabels` would drop the ruled job tag).
     The shape is now a lexer as strict as Groovy's (`wrapperlib.py:474-525`): an identifier (`[A-Za-z_$][A-Za-z0-9_$]*`) or a number is one token, a multi-character operator one token, any other character its own token; a line end (LF, CR or CRLF) is a token, a `//` comment ends at CR, LF or U+FFFF and stands for the line end after it, and runs of line ends collapse to one; only space and tab are skipped.
     Line ends are compared everywhere, inside brackets too, which is stricter than Groovy (it ignores many of them inside `()` and `[]`); the template, the D-generator fixture and the slurm template keep every bracket on one line, so all three still pass.
     The file is read as bytes and decoded, because `read_text`'s universal newlines turned a lone CR into LF before the shape saw it (the lane's CR case was already refused for that reason at `eab4710`; the other cases were admitted there).
   - **L5-R2-2 (MAJOR, from before this change), a descriptor that names no config.** With `name: local` and no `nextflow_config`, or `name: slurm` with `nextflow_config: ''`, in the project's own agent-writable `_config/executor.yaml`, preflight returned early while the wrapper passed its fallback `_config/nextflow.slurm.config` with `-c`, unchecked.
     Preflight no longer returns early: the passed file is the fallback itself, so it is checked like any other against the template its name selects, and refused as missing when absent (review r3, R3-2) (`wrapperlib.py:359-363`), with no second copy of the wrappers' fallback name to drift from it.
     `executorlib.validate` also refuses a blank `nextflow_config` on a backend whose built-in descriptor names one (`executorlib.py:269-270`, today slurm; "R-075: nextflow_config may not be blank for this backend"); on `local` a blank name is the built-in and cannot be told from an absent one after `load`.

Slurm is unchanged for every descriptor whose name is the seeded `nextflow.slurm.config`, including no descriptor at all, for every config the seeded template admits: the same verdicts and the same refusal texts (ExecutorSeamTests, `test_09` untouched, and the trace-grammar test of `test_manifest_groups.py`).
What changes on a slurm workspace is only the refusals above, of names that were never seeded, and, since review r1, of a config whose `fields` string differs from the template's byte for byte (a `//` or whitespace inside it).

Rejected alternatives: a shape comparison for the Batch config (this lane's first design, through reviews r1 and r2, replaced by the render ruling); a union of both grammars under any name (a slurm workspace would admit the Batch grammar under its own name); admitting any file in `_templates/config/` (the assay YAML templates live there); a site value for the clamp or the retry outcomes (no site needs one, and each would widen what an agent-written file can change); `$NXF_HOME` or an `includeConfig` for the missing options (ruled out: a road around the audited surface).

5. **Exact render equality for the Batch config (the coordinator's ruling of 30 Sep 2026).**
   `EXECUTOR_RENDER_SLOTS` (`wrapperlib.py:422-429`) names each rendered template's slots and their validators, fully matched: `queue` `[A-Za-z0-9_-]{1,128}` (the terraform output `batch_job_queue`, an AWS Batch queue name), `goal` `[A-Za-z0-9._-]{1,128}` (the generator's `--job-tag goal=VALUE` allow-list, bounded here), `region` `[a-z]{2}(?:-[a-z]{1,12}){1,3}-[0-9]{1,2}` (an AWS region name); no quote, backslash, newline, `$`, brace or space can be in one.
   The slot values are parsed from the config itself (`rendered_slots`, `:432-452`): the template is split at its slots, its fixed parts escaped, each slot replaced by its validator, and the whole file must match; the values found are rendered back into the template and the rendering must equal the file byte for byte.
   They are parsed rather than read from a declared source because the only other source an agent could set is `_config/executor.yaml`, which is as agent-writable as the config: a second source would add a file to keep consistent with the one passed with `-c`, and could only drift from it, while parsing binds each value to the exact bytes Nextflow is given and admits none outside its validator.
   A config that is not a rendering is refused (`check_rendering`, `:455-468`) as "R-098/§9.6: unregistered Groovy grammar", or, when only a slot value is wrong, "R-098/§9.6: R-075 the <slot> slot must match <validator>"; a missing template is refused before, by `executor_template`. No lexer runs on this road.
   The manifest records, beside the config's own sha256, `execution_config_rendered`: the template's name and sha256, the slot values and the sha256 of the rendering (`:709-725`); a slurm manifest is unchanged.
   The record is never left out silently: prepare keys the rendering check and the record on the DESCRIPTOR's config name, not on the `-c` file's name, and raises before `submit.sh` is written for a `-c` config of another name ("the -c config <x> is not the descriptor's <name>") or one that is not a rendering ("<name> is not a rendering of its template") (review r3, R3-3, and the link rulings; test 18).
   The demo's generator must write this rendering exactly, comments included (the test fixture is one).
   Slurm moving to exact render is a named follow-up after the freeze (R8).

## Threat model of the widening

The widening lets a second grammar through, selected by a name in an agent-writable file (`_config/executor.yaml`), so these are the properties it must keep, each with its code and test:

- **No config outside the two templates is admitted.** For the Batch name, the admitted set is exactly the renderings: the template's bytes with each slot filled by a value its validator admits (item 5); tests 01, 03, 12, 13, 15 and 17 refuse every probe of reviews r1 and r2 under the Batch name, each slot injection (a quote, newline, `${}`, backslash, space, brace, `$`, double quote, empty or over-long value, a malformed region) and every other byte change (a comment, spacing, a blank line, the final newline, CRLF, an expression as the tag value). For slurm, admission is equality with `shape(template)` (`wrapperlib.py:534-535`), the template comes only from `executor_template` (`:527`), which admits only a bare `nextflow.<venue>.config` regular file directly in `_templates/config/` (`:402-413`); today that is two files. Tests 04 and 05 refuse eight additions (one line or one block each) and fifteen changes of fixed tokens (the cliPath among them); test 09 refuses each grammar under the other's name.
- **Nothing hides inside a fixed string, and no boundary moves.** `shape` reads strings before comments, keeps each double-quoted string byte for byte, and compares identifiers, numbers, operators and line ends as Groovy's lexer reads them (`wrapperlib.py:474-525`). Test 15 refuses an identifier split by a space, a newline or a comment, a split number, two statements joined on one line, a no-break space inside an identifier or between two tokens, and a comment ended by CR or U+FFFF, under the Batch name on a rendering and under the slurm name on the slurm template (review r3, R3-1: the table's slurm run keeps the slurm lexer pinned), with comments and blank lines free for slurm only. Test 12 refuses, in each double-quoted string of both templates, a `//` followed by an extra statement and one added space.
- **A name cannot escape `_templates/config/`.** The name pattern has no separator and no dot-dot (`:399`, `:410`), the resolved parent must equal the folder (`:411`), and the descriptor may not name a path (`executorlib.py:266-268`). Test 06 (a missing template, a case-folded name, a `.bak` name, an assay YAML template) and test 07.
- **A template cannot be a file the agent wrote.** `_templates/` is a protected prefix the guard refuses writes to (`guard_hook.py:106`), and a symlink or a folder reached through one is refused (`wrapperlib.py:410-411`). Test 08, with a control proving a regular file of the same bytes selects, so it is the link that refuses.
- **The file checked is the file passed with -c.** `wrapperlib.py:349-391` and `executorlib.py:266-270`. Test 07 plants the evil config at the wrapper's path and a clean decoy where `37a8d94`'s check read, for a subdirectory, a dot-dot and two absolute names, each refused. Test 13 refuses an extra statement behind a nested `_config/_config/executor.yaml`, and test 16 one in the fallback file passed under a descriptor that names no config, and that fallback's absence. A config passed as a symlink is admitted only with the descriptor's name and a realpath inside this workspace's projects, as a replay binds it; test 18 pins a same-named link inside (admitted, its record written), one outside, one to another name, one to a non-rendering, and a chain ending inside or outside.
- **The manifest still records the config bytes.** `execution_evidence` hashes the path the submit body passes after `-c` (`wrapperlib.py:701-707`), unchanged, and for a rendered config also records its slot values and the rendering's sha256 (`:709-725`). Test 10 asserts the recorded sha256 equals the fixture's bytes, the path equals the `-c` token of the generated `submit.sh`, and the render record.
- **Values stay values.** A Batch slot holds only what its validator admits (item 5; tests 03 and 17). A slurm single-quoted literal passes R-075's charset or the config is refused (`wrapperlib.py:514`). Test 03.

## What this does not close

- **R1 (found, then closed after review r2).** A descriptor with `name: local` and no `nextflow_config` demands no config, yet the nf-core wrappers then pass `_config/nextflow.slurm.config` with `-c` (their `paths_for` fallback); at `37a8d94`, and on this branch until review r2, preflight never checked it.
  Closed by L5-R2-2 (item 4) when that file is present, and since review r3 (R3-2) when it is absent too: preflight refuses it with the missing-config precondition ("no _config/nextflow.slurm.config -- stage 00 seeds it"), as for a named config that is missing.
- **R2.** The Batch grammar is selectable by name on any workspace, including a slurm one (`name: slurm` with `nextflow_config: nextflow.awsbatch.config` validates). On a host holding AWS credentials, task files would then move through S3 under a slurm venue's route. Pairing the template with the `local` backend is a one-line rule the coordinator may rule on; it is not in this change.
- **R3.** The bytes are checked at prepare and hashed into the manifest; a rewrite of the config between prepare and the job's start is visible in the manifest's hash, not refused (unchanged from row 6's R9).
  The same holds for a replay's config link re-pointed after the check: the target it pointed to at prepare is what was checked and hashed.
- **R9 (known).** The containment rule judges a `_config/<name>` that is itself a link; a `_config/` folder that is itself a link is judged only by the fence (its name) and by the bytes checked, not by where it resolves.
- **R4 (slurm only since the render ruling; amended after reviews r1 and r2).** For slurm, space and tab between two tokens are still free, and so are comments and blank lines; a split identifier, number, operator or line (L5-R2-1) and whitespace inside a double-quoted string (L5-R1-2) are not.
  This item first said that whitespace inside double-quoted strings was free and that such a change "can only produce a config Nextflow rejects"; the second half was never measured and is withdrawn.
  The lexer is the lane's reading of Groovy's token classes, not Groovy's own lexer; no Nextflow parsed anything here (R5).
- **R6 (disclosed, pre-existing, out of scope; review r2 NOTE R2-4).** The slurm template's `executor = 'slurm'` and its `errorStrategy` outcomes are single-quoted, so they are site values under the slurm name: `executor = 'awsbatch'` passes as a slurm config. The slurm template is unchanged by this change; a later slurm change should make them fixed tokens, as the Batch template does.
- **R8 (named follow-up, after the freeze).** Slurm keeps the shape check; moving it to exact render equality, as the Batch config now is, is a follow-up the coordinator named for after the freeze, with its own records.
- **R7 (known, latent; review r2 NOTE R2-5).** When the passed file's name differs from the descriptor's `nextflow_config`, preflight checks the sibling of that name in the same `_config/` (`wrapperlib.py:364-365`), not the passed file. No wrapper passes such a pair today (each passes `nextflow_config_path` or, with none named, its fallback), so nothing reaches it; it is recorded, not changed.
- **R5.** No Nextflow parsed this template in this lane (no Nextflow on the build Mac, and no AWS use); the first parse is the launch pad's.
- The demo's generator (`gen_executor_config.sh`) is matched to this template by its own lane, not here; until it is, the pad's generated config is still refused.
