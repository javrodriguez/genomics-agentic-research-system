# Machine ownership is enforced by the filesystem, not advised by a comment

## What happened

A fresh run registered 38 samples across 152 FASTQs. Stage 00 reported `ok: true`. Stage 01 then
refused: `files.csv` accounted for 40 of the 152 files.

The user had narrowed the cohort to 10 samples by editing **both** `files.csv` and `samples.csv`.
That is the obvious thing to do — two files list samples, you want ten, you edit both. The
evidence was unambiguous once looked at properly: the surviving rows were a clean subset
(`ALL-p01`…`ALL-p10`) rather than a truncation point, `samples.csv` had the design filled in
(`WT,1,1`…), the do-not-edit banner was still on line 1, and both files had mtimes *later* than
`CONTEXT.md` — which `finalize` writes last.

[0017](0017-machine-owned-files-are-verified-not-trusted.md) had diagnosed an earlier instance of
the same thing as a truncated write from an OOM-killed process. That was wrong, and wrong because
the cause was inferred from symptoms instead of checked against mtimes and content shape.

## The actual defect

`files.csv` said `# generated by stage 00 — do not edit` on line 1 and was mode `0664`.

**A comment is advice. Editors do not read advice.** The system's only defence against a user
doing something reasonable-but-wrong was a sentence, and the consequence surfaced two stages
later as an error message that called their deliberate action "damaged or stale".

## Decision

**Files a stage owns are written mode `0444`.** `files.csv` now is. A user who tries to edit it
gets `Permission denied` from their editor, at the moment of the mistake, instead of a confusing
refusal two stages later.

The stage that owns the file can still replace it: `rename` requires write permission on the
*directory*, not on the target, so `atomic_open`'s temp-then-replace works unchanged and re-applies
the mode afterwards. `finalize` remains the documented repair.

`samples.csv` stays user-writable. It is the user's file, and the split — machine-owned registry,
user-owned design — is [0003](0003-data-model-files-and-samples-split.md). Permissions now make
that split visible without reading a contract.

**The error message was rewritten to match the real cause.** It no longer says "damaged or
stale". It says: this is not how a cohort is narrowed; delete rows from `samples.csv` only; and
re-running `finalize` restores `files.csv` **without touching a design you have already filled
in**. That last clause matters — the previous message implied the remedy would cost them their
work, which would have been true before `finalize` stopped overwriting `samples.csv`.

## The lesson

Enforcement beats instruction, and this project keeps relearning it at a different layer:

- [0002](0002-agent-control-negative-scope-and-templates.md): positive instructions did not
  constrain the agent; negative Scope Boundaries and fixed templates did.
- [0011](0011-deterministic-artifacts-in-stages-00-01.md): telling the agent how to compute an
  artifact did not make it correct; taking the computation away did.
- Here: telling the *user* not to edit a file did not stop them; `0444` does.

When a rule matters, ask what enforces it. If the answer is "a sentence somebody has to read
first", it is not enforced.
