# Row 12 lifecycle and STATUS writer

## Context

Row 12 of specification v1.0.1 §18; R-074, R-076, R-077, R-135,
R-150, R-151 and R-152. Starting commit:
`d17573af63ab5d21d0eadabf806c3da31541f5b6`, the approved row-4 head,
still unmerged. No remote, merge or producer approval is involved.

Number note: 0052–0055 are rows 15 and 4 on other branches; 0056 is the
owner's approval record on row 4. Renumbering at merge is the owner's.

## Decision

The owner's rulings, 22 September 2026, quoted as supplied:

> D-12, ruled 12A: the on-disk terminal success value stays `COMPLETE`; the spec's
> `COMPLETED` names the same state. The writer's closed enum records that mapping in
> one place; no existing STATUS file, contract, `resolve_artifact.py`, `project_state.py`
> or fixture is migrated.

> D-13, ruled 13A: only code writes STATUS. `executorlib` submit writes `SUBMITTED`;
> `status` writes `RUNNING` or the terminal state with the scheduler reason preserved
> (`FAILED:TIMEOUT`, `FAILED:OUT_OF_MEMORY`, `FAILED:NODE_FAIL`, `FAILED:EXIT_<n>`,
> `CANCELLED`); `collect` writes `COMPLETE`; `cancel` writes `CANCELLED`. All through
> one `wrapperlib.write_status()`. An agent session can no longer write a STATUS file:
> the guard refuses it (a new protected pattern for STATUS files under `projects/`),
> and the contract lines that tell the agent to write `SUBMITTED`/`RUNNING`/`FAILED`
> change to the typed `status` call, changing nothing else in those contracts.

The writer accepts the §15 base states CREATED, PLANNED, AWAITING_APPROVAL,
APPROVED, EXECUTING, VALIDATING, REVIEWING, COMPLETE, REJECTED, FAILED,
DIAGNOSING, RETRYING, CANCELLED, PAUSED, NEEDS_INPUT, PARTIAL, STALE,
ARTIFACT_MISSING, plus the existing realised SUBMITTED and RUNNING states.
COMPLETED aliases COMPLETE in one mapping. FAILED may carry only TIMEOUT,
OUT_OF_MEMORY, CANCELLED, NODE_FAIL or EXIT_<nonnegative integer>.
Invalid values raise a typed status_refusal before touching disk.
Atomic replacement fsyncs a unique temporary sibling, then uses os.replace;
concurrent writers cannot share a temporary file. All ten wrappers
call this writer only after their collect gates. A successful write additionally
requires the completion marker and the collected output index.

R-077 changes executor JSON `state` values from bare FAILED to CANCELLED,
FAILED:TIMEOUT, FAILED:OUT_OF_MEMORY, FAILED:NODE_FAIL and FAILED:EXIT_<n>.
`terminal` includes cancellation and qualified failure. R-135 introduces
ARTIFACT_MISSING when recorded scheduler success has no marker; unreachable
scheduler calls retain an error response and persist STALE. R-076 submission
refusals add a typed `refusal` object and exit 2; successful job_id output is unchanged.
The typed tool envelope is unchanged; executor.status's side-effect declaration now
names its STATUS refresh, while the explicit reviewer status permission remains.

R-076 keys are computed from exact params.yaml, samplesheet and assay config bytes,
in that order. Prepare puts only this new key into the manifest and a submit.sh
comment after the unchanged script/header. A project-local file lock and pre-submit
reservation prevent concurrent duplicate side effects. Ambiguous scheduler outcomes
retain the reservation. These files are a repo-side submission guard, not the Stage-3
state table. Missing keys refuse submission; recorded failed keys refuse retries
pending the unresolved R-152 policy. No work directory is deleted or moved.

Decision 0039's descriptor/header seam is preserved. The exact historical seeded
Slurm map and status argv are recognized in memory and replaced by the new built-in
values (R-077); unrelated overrides still refuse. No descriptor on disk is rewritten.
Decision 0038's resume-refresh gate and the generated .gars_run_complete/-resume
branches stay unchanged. A separate test executes their generated bytes on a scratch
local fixture; that is not approval to retry or the required Slurm-path proof.

## Owner rulings needed

1. **Scheduler success before collect (R-135 versus ruling 13A).** The scheduler can
   finish successfully before collect has validated outputs. Options: persist VALIDATING
   while preserving COMPLETED in the scheduler JSON until collect writes COMPLETE; or
   another owner-selected non-success state. Never publish COMPLETE from scheduler
   success alone. This part waits for the owner.
2. **Failure taxonomy (R-152).** The spec lists classes but gives no exit-code mapping
   for them. Options: retain the existing transient set 104 and 130–145 when no specific
   scheduler failure overrides it; assign scheduler TIMEOUT/OUT_OF_MEMORY/NODE_FAIL to
   infrastructure, 126/127 to tool, 65 to data_quality, and other nonzero exits to
   workflow, leaving agent_reasoning/scientific_validation unassigned until their
   producers define codes; or supply different mappings. The choice and destructive
   retry approval binding wait for the owner. No synthetic agent/science codes are invented.
3. **Cancellation approval binding (R-074).** Row 4 authenticates a stage-03 PLAN.md,
   not a job action. Options: a job-specific cancellation plan using the existing
   protected store, with explicit job/backend identity and an issuance path; or an
   owner-selected action record extension. Reusing an unrelated run approval would not
   approve cancellation. This binding waits for the owner; no CLI approval flag or
   environment override is acceptable.
4. **Downstream idempotency inputs (R-076).** Three downstream wrappers have no
   params.yaml; rnaseq-de's manifest inputs have counts/design rather than samplesheet.
   Options: serialize their existing parameter lists to params.yaml and use the assay's
   stage-01 samplesheet; or define a separate downstream key. This part waits for the owner.
5. **Out-of-bound writers (R-151/R-135).** stage03_analysis.py writes COMPLETE inline
   without a .gars_run_complete gate; the authoring generator emits inline writes too.
   Both are outside this row's edit boundary. Options: leave both explicitly NOT met;
   or authorize narrowly scoped changes and tests. The sweep for this row covers the
   ten shipped wrappers and executorlib, not those out-of-bound paths.

6. **Raw scheduler submission in four contracts.** The scrnaseq/spatialvi first and
   downstream contracts still instruct raw sbatch, which the row-4 guard refuses.
   Ruling 13A permits changing STATUS instructions only. Options: authorize these
   submit lines to use executor.submit as their reviewed skills already do; or retain
   the refusal until a separate contract change. No extra contract lines are changed.
