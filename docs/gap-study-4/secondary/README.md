# Gap Study round 4: the reader-gap secondary analysis, and how to regenerate it

This folder publishes the code, the pre-registration and the recorded inputs of round 4's pre-registered secondary (sensitivity) analysis, whose report is `evals/gap-study-4/SECONDARY.md` (sha256 `b09bc48f746610cfa85bdaaeaefa09a6fd8a061833e855cf29be0b5e027ebaa7`, the hash `docs/EVALS.md` cites).
The headline claim of round 4 rests on the primary analysis; this is the sensitivity analysis beside it.
It was built on 13 Nov 2026 on a branch from the post-run head `1e097b2f5f99a4d5134234d5553dcb8cdaff45ca` (19 commits before the verified head `1ded8e9a2ada`, and an ancestor of it), and is published here after the verified head; no file of the study line was changed to publish it.

## What is here

- `reader_gap_secondary.py`, `transcript_view_secondary.py`, `tests/test_reader_gap_secondary.py` and `tests/test_reader_gap_secondary_driver.py`: byte-identical to the files at `evals/gap-study-4/` on the analysis branch's head `dcc3538d5f3af0e4750b94512b8fecd6225cb2d2`, the paths `SECONDARY.md` names.
- `gap-study-4-reader-gap-sensitivity-PREREG-20261108.md`: the pre-registration, written 8 Nov 2026 before any result was read, copied unchanged under one added header line that names its source and sha256.
- `inputs/`: the five recorded files the 13 Nov run's `report` step read, byte-identical to the files on the study's run machine, with `inputs/SHA256SUMS`.

The code sits here and not under `evals/gap-study-4/` because the study's own check (`copy_manifest.py --later-files`, run by `result.py --check`) refuses an importable file added under that folder after the freeze.
It does not run in place: `reader_gap_secondary.py` refuses unless `transcript_view_secondary` loads from the graded tree's `evals/gap-study-4/`, and both tests read the study modules from their parent folder.
So the command below stages it in a scratch checkout of `1e097b2f5f99`.

## What re-derives, and what is a recorded input

| File | How it is checked from a clone |
|---|---|
| `inputs/grades-frozen.json`, `inputs/grades-patched.json` | Re-derived, equal to the published files in every field but `tree`. `tree` is the absolute path of the checkout `grades` graded (in the published files, the run machine's two checkouts), so no grade file made in another folder can equal these byte for byte; the compare below removes nothing and prints the keys that differ, and passes only when that list is `[]` or `["tree"]`. |
| `inputs/check.json` (the blind check, plan item 3) | Re-derived byte for byte from the two re-derived grade files (`cmp`). |
| `evals/gap-study-4/SECONDARY.md` | Regenerated byte for byte from the five published inputs (`cmp`). |
| `inputs/attempt1-check.json` | A recorded input, not re-runnable: the first attempt's check, made with an in-place edit of `transcript_view.py` that is disclosed in `SECONDARY.md` and is not published. |
| `inputs/shapes-detail.json` | A recorded input: the frozen reader's line-by-line refusals for the two unreadable takes, made on the run machine by a helper script that is not published. |

The final `report` run of 13 Nov was given exactly these inputs: `grades-frozen.json` (graded on a checkout of `1e097b2f5f99` without the four files), `grades-patched.json` (graded on the branch checkout with `--secondary`), `check.json`, `attempt1-check.json`, `shapes-detail.json` and `--base 1e097b2f5f99a4d5134234d5553dcb8cdaff45ca`.

## Run it

From the root of a clone of this repository, with Python 3.11 or later (the `-P` flag) and nothing else installed (standard library only).
The grading steps read every committed take of round 4 and need about 3 GB of disk space for the two scratch checkouts.

```sh
REPO=$(pwd)
SCR=$(mktemp -d)                                   # any empty folder outside the clone
SEC=docs/gap-study-4/secondary
git worktree add --detach "$SCR/branch" 1e097b2f5f99a4d5134234d5553dcb8cdaff45ca
git worktree add --detach "$SCR/frozen" 1e097b2f5f99a4d5134234d5553dcb8cdaff45ca
for f in reader_gap_secondary.py transcript_view_secondary.py tests/test_reader_gap_secondary.py tests/test_reader_gap_secondary_driver.py; do
  cp "$SEC/$f" "$SCR/branch/evals/gap-study-4/$f"
done
(cd "$SCR/branch/evals/gap-study-4/tests" && python3 -B -m unittest test_reader_gap_secondary test_reader_gap_secondary_driver)
D="$SCR/branch/evals/gap-study-4/reader_gap_secondary.py"
mkdir "$SCR/out"
python3 -B -P "$D" grades --tree "$SCR/frozen" --out "$SCR/out/grades-frozen.json"
python3 -B -P "$D" grades --tree "$SCR/branch" --secondary --out "$SCR/out/grades-patched.json"
python3 -B -P "$D" compare --frozen "$SCR/out/grades-frozen.json" --patched "$SCR/out/grades-patched.json" --out "$SCR/out/check.json"
for g in grades-frozen.json grades-patched.json; do
  python3 -c 'import json,sys; a,b=(json.load(open(p)) for p in sys.argv[1:]); d=sorted(k for k in a.keys()|b.keys() if k not in a or k not in b or a[k]!=b[k]); print(d); sys.exit(d not in ([],["tree"]))' "$SCR/out/$g" "$SEC/inputs/$g"
done
cmp "$SCR/out/check.json" "$SEC/inputs/check.json"
python3 -B -P "$D" report --tree "$SCR/branch" --check "$SEC/inputs/check.json" --attempt1 "$SEC/inputs/attempt1-check.json" \
  --shapes "$SEC/inputs/shapes-detail.json" --base 1e097b2f5f99a4d5134234d5553dcb8cdaff45ca \
  --frozen-grades "$SEC/inputs/grades-frozen.json" --patched-grades "$SEC/inputs/grades-patched.json" --out "$SCR/out/SECONDARY.md"
cmp "$SCR/out/SECONDARY.md" evals/gap-study-4/SECONDARY.md
(cd "$SEC/inputs" && shasum -a 256 -c SHA256SUMS)
git worktree remove --force "$SCR/branch"; git worktree remove --force "$SCR/frozen"
```

Each `cmp` prints nothing and each compare prints `['tree']` when the analysis reproduces.
The tests read `git show 1e097b2f5f99:evals/gap-study-4/transcript_view.py`, so the scratch trees must be worktrees of a clone, not plain copies.
The first `grades` run is the frozen reader on the unpatched checkout; the second installs the patched reader at runtime (`--secondary`); `transcript_view.py` is the frozen file in both, which `compare` checks by hash.
