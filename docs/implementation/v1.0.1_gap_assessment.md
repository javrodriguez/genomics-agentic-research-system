## How this was produced, and what counts as evidence

- The fifteen §18 rows were split across six read-only evidence passes, each a fresh sub-agent with no write access to the repository. Each read the specification sections its rows cite, searched the tree, and ran only read-only probes. The producer then consolidated the results and re-derived the load-bearing claims itself.
- **Classification rules.**
  - **PASS**: the row's exit test exists and passes when run. No row reached this.
  - **PARTIAL**: at least one of the row's artifacts exists, in place or under another name, with the evidence cited.
  - **MISSING**: none of the row's artifacts exists.
  - **BLOCKED**: an external dependency outside the repository stops progress: hardware, an owner decision, or data. Depending on another unbuilt row is MISSING, not BLOCKED.
- **PASS needs evidence.** Names, comments, README/DEVELOPMENT prose, commit messages and memory never count.
- **Probes** were small scripts run from the producer's scratch directory against copies or crafted stdin. They are not in the repository. The reviewer should re-derive every finding marked *probe* rather than trust it.
- **Re-derived by the producer in this session** (commands below):
  - The guard hook exits 0 (allow) on unparseable stdin, on `git push --no-verify`, and on a `python3 -c` write into `_system/`. A shell redirect into `_system/` is blocked (exit 2). `guard_hook.py:208-211` is `except Exception: sys.exit(0)  # nothing to judge; allow`.
  - `executorlib.py cancel` → `invalid choice: 'cancel' (choose from header, submit, status, describe)`.
  - `executorlib.py:41` `STATES = ("PENDING", "RUNNING", "COMPLETED", "FAILED")`; the Slurm map folds `CANCELLED`, `TIMEOUT`, `NODE_FAIL` and `OUT_OF_MEMORY` into `FAILED`.
  - Stage 03 approval is a text match: `stage03_analysis.py:265` `re.search(r"^Status: APPROVED( .*)?$", text, re.M)`.
  - Decision citations in code and contracts: 240 occurrences (134 code, 106 `gars/**.md`), 29 distinct numbers, 0 unresolved by filename.
